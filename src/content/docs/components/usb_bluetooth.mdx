The `usb_bluetooth` component connects a USB Bluetooth dongle (a USB HCI controller) to an ESP32 with a USB host
port: the ESP32-S2, ESP32-S3, ESP32-S31, ESP32-P4 and ESP32-H4. It builds on the [USB Host](/components/usb_host/)
component.

The dongle can be used in two ways:

- **Detection only** (the default): the controller is reset and identified, and its Bluetooth version, manufacturer,
  address and name are logged. This is useful for checking that a dongle works before using it.
- **As the controller of `esp32_ble`**: with `bluedroid: true`, the ESP-IDF Bluedroid host runs on the dongle
  instead of on a built-in radio or an [ESP32 Hosted](/components/esp32_hosted/) co-processor. Everything built on
  [ESP32 BLE](/components/esp32_ble/) then uses the dongle, including the
  [Bluetooth Proxy](/components/bluetooth_proxy/), [ESP32 BLE Tracker](/components/esp32_ble_tracker/) and
  [BLE Client](/components/ble_client/). This gives Bluetooth to chips without a radio, like the ESP32-P4, and lets
  the radio sit at the end of a USB cable, away from the ESP32. The dongle can also stream audio to a Bluetooth
  speaker over Classic Bluetooth; see [Bluetooth Speaker](#bluetooth-speaker).

```yaml
# Example configuration entry
usb_bluetooth:
```

The [USB Host](/components/usb_host/) component is loaded automatically; configure it for options such as
`max_packet_size` or `enable_hubs`.

## Configuration Variables

- **id** (*Optional*, [ID](/guides/configuration-types/#id)): The id to use for this component.
- **vid** (*Optional*, int): The USB vendor ID of the dongle. Defaults to `0`, which matches any device.
- **pid** (*Optional*, int): The USB product ID of the dongle. Defaults to `0`, which matches any device.
- **manufacturer** (*Optional*, string): Only match a dongle whose USB manufacturer string is exactly this.
- **product** (*Optional*, string): Only match a dongle whose USB product string is exactly this.
- **interface_description** (*Optional*, string): Only match a dongle one of whose USB interfaces has exactly this
  interface string.
- **firmware** (*Optional*, filename): A Realtek firmware file to download into the controller at every start. See
  [Realtek Dongles](#realtek-dongles).
- **firmware_config** (*Optional*, filename): The Realtek configuration file that belongs with `firmware`. Requires
  `firmware`.
- **bluedroid** (*Optional*, boolean): Use this dongle as the controller of the Bluedroid host of
  [ESP32 BLE](/components/esp32_ble/). Requires `esp32_ble` and cannot be combined with `esp32_hosted`. Only one
  `usb_bluetooth` entry can set this. Defaults to `false`.
- **a2dp_speaker** (*Optional*, MAC Address): The Bluetooth address of a speaker (an A2DP sink) to connect to and
  stream audio to, using the [USB Bluetooth Speaker](/components/speaker/usb_bluetooth/) platform. Requires
  `bluedroid: true`, and turns on Classic Bluetooth (BR/EDR) in Bluedroid next to Bluetooth LE. Not needed with a
  [Speaker Select](#speaker-select); a speaker chosen there takes the place of this one.
- **on_speaker_volume** (*Optional*, [Automation](/automations/)): Runs when the volume is changed on the speaker
  itself. The level from `0` to `1` is in the variable `x`. Use it to let a media player follow the speaker; see
  [Speaker Buttons and Volume](#speaker-buttons-and-volume). Needs `a2dp_speaker` or a
  [Speaker Select](#speaker-select).
- **pause_ble_scan** (*Optional*, string): When the BLE scan of
  [ESP32 Bluetooth Low Energy Tracker](/components/esp32_ble_tracker/) (and so the Bluetooth proxy) stops for a while
  to leave the radio to the speaker. One of `connecting` (while the speaker connects and while a search runs),
  `streaming` (also for as long as audio streams) or `never`. Only a scan that is running is paused, and it starts
  again afterwards. Needs `a2dp_speaker` or a [Speaker Select](#speaker-select). Defaults to `connecting`.

With `vid` and `pid` left at `0`, the component takes the first connected device with a Bluetooth controller interface
(USB class `E0`, subclass `01`, protocol `01`) and ignores every other device. More than one entry is allowed, but then
each needs a `vid` and `pid`. The matching filters work as described for
[USB Host devices](/components/usb_host/#device-configuration-options).

## Realtek Dongles

Most cheap USB Bluetooth 5 dongles (for example the TP-Link UB500 and others with the RTL8761BU chip) start with
firmware in ROM that is too old to be used. Like the Linux `btrtl` driver, the component downloads a firmware patch
into the controller each time it starts. The firmware is not included in ESPHome: download the files for your chip
from the `rtl_bt/` folder of
[linux-firmware](https://git.kernel.org/pub/scm/linux/kernel/git/firmware/linux-firmware.git/tree/rtl_bt)
and put them next to your configuration. For the RTL8761BU these are `rtl8761bu_fw.bin` and `rtl8761bu_config.bin`.

The file is checked when the configuration is validated, and the patch that matches the ROM version reported by the
controller is chosen at run time. A firmware fragment is sent as one USB control transfer of more than 256 bytes, so
the [USB Host](/components/usb_host/) `max_packet_size` must be set to `512` or more.

When the download works, the log shows the controller with its new version:

```text
[I][usb_bluetooth]: Controller ready: Bluetooth 5.1, Realtek Semiconductor, address 8C:90:2D:xx:xx:xx, name "UB500"
```

Dongles that need no firmware (for example many with Intel, Broadcom or CSR chips) can be used without `firmware`.
Only the RTL8761BU has been tested so far.

## Notes

- On the ESP32-P4, a full-speed dongle connected through a hub (including a hub built into the development board)
  needs `full_speed_only: true` on [USB Host](/components/usb_host/), because the ESP-IDF USB host does not support
  split transactions.
- With `bluedroid: true`, the USB host library runs in its own task instead of in the main loop, so that Bluedroid
  can wait for the dongle's replies while it starts.
- When the dongle is unplugged, Bluetooth is stopped; when it is plugged back in, it is set up again and Bluetooth
  is restarted. Connections made through the dongle are lost when it is unplugged.
- Without `a2dp_speaker` or a [Speaker Select](#speaker-select), only Bluetooth LE is used. Classic Bluetooth is
  only used for streaming to a speaker.

## Bluetooth Speaker

The dongle connects to the speaker set with `a2dp_speaker` or chosen with the [Speaker Select](#speaker-select),
over Classic Bluetooth, and keeps the connection up: it
connects again when the speaker is switched on or comes back in range, and the speaker can also connect to the
ESP32 itself. A speaker that does not answer is tried again after 10 seconds, then after 20 and 40 seconds, and from
then on once a minute; while there is audio to play it is tried every 3 seconds. Audio goes to the [USB Bluetooth Speaker](/components/speaker/usb_bluetooth/) platform, usually through a
[Speaker Media Player](/components/media_player/speaker/).

- The first time, put the speaker in pairing mode. Pairing needs no input: Secure Simple Pairing is confirmed
  automatically, and a speaker that asks for a PIN gets `0000`.
- The volume is sent to the speaker over AVRCP (absolute volume), so the speaker's own volume follows the media
  player. A speaker without absolute volume gets the samples scaled instead.
- The stream starts when audio comes and is suspended a few seconds after it stops; the connection stays.
- The address of a speaker is shown in the Bluetooth settings of a phone or computer it has been paired with, or on
  a label on the speaker. With the [Speaker Select](#speaker-select) it is not needed.
- Only the chosen speaker stays connected; another device that connects is disconnected.

### Speaker Select

The `usb_bluetooth` select platform chooses the speaker the way a phone does. Its options are the current speaker,
the audio devices (speakers, headphones, radios) found by the last search, and **Search for speakers**, which searches
for 13 seconds. Put the speaker in pairing mode, choose **Search for speakers**, and choose the speaker once it is
listed. The device with the strongest signal, usually the nearest one, is listed first. A device that sends no name
during the search is asked for it afterwards, so it is listed by name instead of by its address. The choice is kept
in flash, with the name the speaker reports when it connects (also for a speaker set with `a2dp_speaker`).

```yaml
select:
  - platform: usb_bluetooth
    speaker:
      name: "Bluetooth speaker"
```

- **usb_bluetooth_id** (*Optional*, [ID](/guides/configuration-types/#id)): The `usb_bluetooth` entry to use. It
  must have `bluedroid: true`. Defaults to the only one in YAML.
- **speaker** (**Required**): The speaker select. All options from [Select](/components/select/#config-select).

> [!NOTE]
> Home Assistant reads the options of a select when it connects to the device, so speakers found by a search show
> up there after the ESPHome integration is reloaded. In the [Web Server](/components/web_server/) they show up
> after the page is reloaded.

### Speaker Text Sensors

The `usb_bluetooth` text sensor platform shows the speaker that is connected, as its name and address (for example
`SBL 4 A2 (4C:72:74:24:C8:05)`), and what the link to the speaker is doing.

```yaml
text_sensor:
  - platform: usb_bluetooth
    connected_speaker:
      name: "Connected speaker"
    speaker_status:
      name: "Speaker status"
```

- **usb_bluetooth_id** (*Optional*, [ID](/guides/configuration-types/#id)): The `usb_bluetooth` entry to use. It
  must have `a2dp_speaker` or a [Speaker Select](#speaker-select). Defaults to the only one in YAML.
- **connected_speaker** (*Optional*): The connected speaker; empty while no speaker is connected. All options from
  [Text Sensor](/components/text_sensor/#config-text_sensor).
- **speaker_status** (*Optional*): One of `No speaker` (none chosen), `Searching`, `Connecting`, `Not reachable`
  (the last attempt failed; the speaker is off or out of range), `Connected` or `Playing`. All options from
  [Text Sensor](/components/text_sensor/#config-text_sensor).

### Speaker Buttons and Volume

The `usb_bluetooth` event platform reports the buttons pressed on the speaker, with the event types `play`, `pause`,
`stop`, `next` and `previous`. A speaker without absolute volume also sends `volume_up` and `volume_down`. In Home
Assistant the event can start an automation, for example to skip to the next song in Music Assistant. Which event a
button sends is up to the speaker: many send `play` both to start and to pause. Not every speaker sends these
buttons: play, pause, next and previous need AVRCP controller category 1, and many small speakers only have
category 2 (volume). The log says so when the speaker connects.

The volume buttons of a speaker with absolute volume change the speaker's own volume. With `on_speaker_volume`, the
media player follows it, so Home Assistant shows the same level.

```yaml
usb_bluetooth:
  - bluedroid: true
    a2dp_speaker: 4C:72:74:XX:XX:XX
    on_speaker_volume:
      - media_player.volume_set:
          id: bt_media_player
          volume: !lambda return x;

event:
  - platform: usb_bluetooth
    speaker_buttons:
      name: "Speaker buttons"
```

- **usb_bluetooth_id** (*Optional*, [ID](/guides/configuration-types/#id)): The `usb_bluetooth` entry to use. It
  must have `a2dp_speaker` or a [Speaker Select](#speaker-select). Defaults to the only one in YAML.
- **speaker_buttons** (**Required**): The buttons on the speaker. All options from
  [Event](/components/event/#config-event).

## Examples

### Bluetooth Proxy on a USB Dongle

An ESP32-P4 with Ethernet as a [Bluetooth Proxy](/components/bluetooth_proxy/), with a Realtek RTL8761BU dongle as
its radio:

```yaml
usb_host:
  max_packet_size: 512  # Needed to download Realtek firmware

usb_bluetooth:
  - firmware: firmware/rtl8761bu_fw.bin
    firmware_config: firmware/rtl8761bu_config.bin
    bluedroid: true

esp32_ble:

bluetooth_proxy:
  active: true
```

### Bluetooth Speaker as a Media Player

A Bluetooth speaker as a [Speaker Media Player](/components/media_player/speaker/) in Home Assistant. A
[Resampler Speaker](/components/speaker/resampler/) converts the 48 kHz of the media player to the 44.1 kHz of
Bluetooth audio:

```yaml
usb_bluetooth:
  - firmware: firmware/rtl8761bu_fw.bin
    firmware_config: firmware/rtl8761bu_config.bin
    bluedroid: true
    a2dp_speaker: 4C:72:74:XX:XX:XX

esp32_ble:

speaker:
  - platform: usb_bluetooth
    id: bt_speaker
  - platform: resampler
    id: bt_resampler
    output_speaker: bt_speaker

media_player:
  - platform: speaker
    name: "Bluetooth speaker"
    announcement_pipeline:
      speaker: bt_resampler
      format: FLAC
      sample_rate: 48000
      num_channels: 2
```
